- 此前误提交的 `Packages/com.farlocus.locus` 插件是残缺编译快照（`CaptureViewportRequest`/`MonoMod` 缺失、`unsafe` 未开、依赖缺失）。本机仍保留可编译的完整插件版本；现在该插件已从 Git 及 `Packages/packages-lock.json` 移除；`.gitignore` 仍排除本地插件目录，当前环境可继续保留本地文件而不会进入仓库。
- UI 按钮「点了没反应」不能只用 `Button.onClick.Invoke()` 验收：射线被上层 Graphic 挡住时 Invoke 仍会成功。验收交互必须用 `EventSystem.RaycastAll` + `ExecuteEvents` 走真实射线路径。实例：`StartScene` 论坛面板标题栏关闭按钮被美术新增的 `ForumPanel/PopupDragonWindow2/Frame/Content/Title (1)`（TMP 文字、`raycastTarget=true`）吞掉点击，把该文字 `raycastTarget` 置为 false 后恢复。同类隐患：`SettingsPanel/Title`、`HistoryPanel/Title` 也是 `raycastTarget=true`，纯文字标签应统一设为 false。
- 横向拉伸锚点（`anchorMin.x != anchorMax.x`）的 RectTransform 上写 `sizeDelta.x`，实际宽度 = 父级宽度 + sizeDelta，而不是 sizeDelta。实例：`PileHoverPanel/RowContainer/PileRow/Content` 是拉伸锚点，`BattleMaterialRowUI.Refresh` 设 `sizeDelta.x = 800` 后实际宽 892+800=1692，而箭头行以 Content 左边缘为 x=0 排布，导致 Hover 面板里箭头整行偏左溢出（面板内不居中）；`BattleMaterialRowUI` 里检测到拉伸锚点就收敛为居中固定锚点后恢复。该类容器在设置尺寸前先确认锚点语义。
- 保存场景会把脚本里已改名/删除的序列化字段“按新名 + 代码默认值”重写，旧名下的调参值直接消失（运行时其实早已读不到旧名值）。实例：`SampleScene_PC` 中 `HandSystemUI` 仍存着 `resolveMotionSpeedMultiplier 2 / castProjectileSpeedMultiplier 1.5 / comboResolveSpeedStep 0.1`，而脚本已改成 `resolveSpeedMultiplier / comboSpeedStartLayer / comboSpeedStep`；一次例行存盘把这些行改写为 1.1 / 5 / 0.05，导致美术/手感调过的数值在 YAML 里无法找回。改名字段时要同步加 `[FormerlySerializedAs]` 或先把旧值从场景里抄出来，才能安全保存场景。
- 血量颜色曾被硬编码在代码里并在运行时覆盖美术设定：`HealthBarUI` 用 `healthFillColor`（默认 #70C517）同时画血条和血量数字，`SetHealthTextColor` 把血量数字写死 #F2140A；`HandSystemUI` 6324-6327 把敌人血条/缓冲/护盾写死 #D10D0A / #FFFFFF / #338CFF。后果是 `SampleScene_PC` 美术设的 #44C85E（`HealthBarBack/HealthFill` 与 `HealthText`）运行中被改成 #70C517，其余三个场景 `HealthText` 的美术色（#8AF11F）也全部失效。修复：代码不再写任何颜色（删除颜色字段与 `SetHealthTextColor`），颜色只取自 Scene/Prefab 上的 Graphic/TMP，代码只负责长度/层级/alpha。验收：Play Mode 进入一场战斗后对比 `EnemyViewUI`、`PlayerStatusUI` 的 `HealthFill`/`HealthText.color` 与预制体/场景值。
- 全屏遮罩（暗色 dim）不能只当作“面板的背景”处理：如果它是面板节点的**兄弟**节点，只 `SetActive(false)` 面板会把遮罩留在屏幕上，而 Image 默认 `raycastTarget=true` 会吞掉所有点击（表现为“卡死、点不动”）。实例：自建的隐私弹窗兜底面板 `PrivacyConsentPanel`，`Overlay`（整屏 Image）与 `Panel` 是兄弟，`Hide()` 只关了 `panelRoot`，玩家点“同意”后面板消失但暗滤镜还在且无法交互。修复：改成统一切换“整屏遮罩 + 面板”的显隐（兜底面板连 Canvas 根一起切）；美术面板如果遮罩也是兄弟节点，需拖到新增的 `dimOverlay` 字段。验收时不能只看“面板消失了”，必须用 `EventSystem.RaycastAll` 看屏幕中心最上层命中是不是遮罩。
- 道具瀑布（`ItemWaterfallEffect` / `ItemFallingPiece`）不要用「碎片停稳后把刚体转成 Static」来省物理开销：碎片一旦被回收/到期消失，压在它上面的碎片会失去支撑，代码必须再补一套「移除时解冻上方碎片」的判定，仍容易留下悬空碎片（本次已回退该实现）。正确做法是碎片始终 Dynamic、堆积体靠物理自然塌落；性能只从对象池复用（不反复 `Destroy/Instantiate`）与控制器统一 Tick 驱动去省，代码不写 `Rigidbody2D.bodyType`。
- Unity 2022.3 编辑器的一个已知崩溃点：**Build Settings 窗口的 Android 平台选项在重绘时会自己抛异常并直接崩溃**。`Logs/Editor.log` 表现为 `GUI Error: Invalid GUILayout state in view. Verify that all layout Begin/End calls match` → `ArgumentException: Getting control 1's position in a group with only 1 controls when doing repaint` + `Aborting`，调用栈落在 `UnityEditor.Android.AndroidBuildWindowExtension.DoTargetListUnsafe()` / `DoTargetList()` → `BuildPlayerWindow.ShowBuildTargetSettings()`，随后是 `Native Crash Reporting ... Got a UNKNOWN while executing native code`（托管栈为空）。与项目脚本/场景无关，不会损坏已保存的项目文件（本次崩溃后 `git diff HEAD -- Assets/Scenes/*.unity` 为空、场景内容完整）。规避：不要在 Build Settings 窗口开着的时候切平台/改 Target 列表，切平台前先把窗口关掉；崩溃后直接重启编辑器，不用做修复。
- 编辑器在 **Android 构建成功后**也可能原生崩溃（2026-10-02）：`Logs/Editor.log` 里先有 `Build completed with a result of 'Succeeded'`，接着是 TapSDK 自己的 `TapSDK.Core.Editor.LinkXMLGenerator.DeleteGeneratedFiles()`（删 `Assets/TapSDK/{Core,Login}/link.xml`，`EditorApplication.delayCall` 里执行）→ `Asset Pipeline Refresh` → `[locus-native] client disconnected/connected` → `Native Crash Reporting ... Got a UNKNOWN while executing native code`（**托管栈为空**）。构建产物是成功的（与项目脚本/场景无关），暂未定位到单一原因，但崩溃点紧跟在“刚构建完的 delayCall 删资产 + 资产刷新 + Locus 原生桥重连”之后；建议复现时先确认是不是每次构建后都崩，并试一次不让 Locus 连接/空闲时构建，以判断是不是插件参与。
- 项目 UI 字体（`UIManager.GetDefaultTMPFont()` → `FZG_CN SDF`，无 fallback 表）**缺部分符号字形**，做了中文新文案必须查：已确认缺 `「」（U+300C/300D）` 与 `〈〉（U+3008/3009）`、全角 `～（U+FF5E）`、`〜`、`・`、`◆`、`※`、`★`；可用：`“”`、`‘’`、`《》`、`【】`、`、`、`。`、`，`、`·`、`•`、`●`、`—`、`…`、ASCII `~`、`（）`、`？`。验证方法：不能用 `TMP_FontAsset.HasCharacter()`（对本字体两个方向都判错），要么 Play Mode 截图肉眼确认，要么看控制台警告 `The character with Unicode value \uXXXX was not found in the [FZG_CN SDF] font asset ... in text object [X]`（注意控制台会保留旧条目，需用唯一对象名或强制重渲染区分）。排查技巧：造一行候选符号（如 `「A」B【C】D“E”F…`）渲染一次，直接从警告里读出缺哪些码位。
- `SpringLineHighlightUI` 的 `hideOnAwake=true` 会在 `Awake()` 里 `gameObject.SetActive(false)`（供“悬停才显示的高亮线”用）。**不能把面板内容挂在它下面**：弹窗的 `Frame` 一挂这个组件，运行期整棵子树（正文+按钮）都会 inactive，Edit Mode 里却完全正常。实例：`TestDataConsentPanel/PopupDragonWindowBackground/Frame/Content`（正文+同意/不同意按钮都是 Frame 的子节点），Play Mode 下 `Frame.activeSelf=False` → 按钮 `activeInHierarchy=False`，射线完全打不到。修法：把该 Frame 的 `hideOnAwake`/`bindHoverTarget` 关掉，让它像其他弹窗一样常显；或把内容移出 Frame。验收必须进 Play Mode 看 `activeInHierarchy` 与 `EventSystem.RaycastAll`。
- `LocalizedTMPText` 会在运行期用**本地化表的值**覆盖 TMP 文本，**只有表里没这个 key / 值为空时才回填组件上的 `fallback`**。所以美术直接在 Scene 的 TMP 里写的文案在 Edit Mode 看得见、运行时会被表里的文案替掉。实例：`TestDataConsentPanel` 的 Body（key `ui.test_data.body`，zh-CN 表里的值是我早先写的旧概括文案）——美术在场景里写的富文本“施工中”版在 Play Mode 变成了表里那个旧文案。处理：要么删掉这些节点上的 `LocalizedTMPText` 让场景文本生效，要么把美术这版文案写进表。**删组件前先看英文表**：`ui.test_data.*` 在 en-US 里有现成英文（“Welcome to Oxy Dungeon!...”），删组件后英文版会直接显示中文场景文案（本次就是如此，取舍已告知用户）。
- 本地化 JSON 的条目字段是 `key` + **`text`**（不是 `value`）。用脚本读表时把字段名写错，会把**所有**条目都读成空串，从而得出“表是空的、运行时回填 fallback”这种错误结论，进而影响到“删组件还是填表”的决策（本次踩过：读表统一用 `text`）。
