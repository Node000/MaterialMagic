# 脚本规则入口与验收

本页对应 `Assets/Docs/逻辑表现分离实施计划.md` 的实际接口。正式 UI 与脚本使用相同 BattleCommandSession / BattleTurnDriver、选择与经济会话；GameSession 可无场景推进整局，Standalone 工程链接相同生产源在 Unity 外运行。历史首批结果与本批最终验证分开记录，不以源码存在代替运行通过。

## 无场景完整回合

以下集合写入仅用于测试初始状态。正常操作应通过 BattleCommandSession 或 GameSession.Execute；不调用正式存档或图鉴。构造时可显式传入 RuleContentSnapshot、RuleProfilePolicy 和 RunDifficultySaveData。

```csharp
var player = new PlayerStatus(50, 10, PlayerStateServices.Simulation,
    new RunDifficultySaveData(), new RuleContentSnapshot(), RuleProfilePolicy.Empty);
player.SetRunRandomState(12345, 0);
var battle = new BattleManager(player);
try
{
    battle.AddEnemy(new EnemyModel(new EnemyData
    {
        numericId = 99001,
        string_id = "simulation_example",
        maxHealth = 20
    }));
    battle.BeginPlayerTurn();
    player.PlayZone.Add(new MaterialModel("example_fire", MaterialEnum.Fire));

    BattleTurnResult result = BattleTurnDriver.ResolveTurn(
        battle, magics: player.MagicBook, nextTurnDrawCount: 0);
    // result.Steps / EnemyIntents / FinalState 可供断言和诊断。
}
finally
{
    BattleManager.ClearInstance(battle);
    MaterialModifierModel.CurrentContext = null;
    MagicModifierModel.CurrentContext = null;
}
```

`BattleTurnDriver` 在返回前提交完整回合，正式 UI 的 ResolveCommittedBattleTurn 也直接调用它，再播放 InitialState / Steps / FinalState。传入 `tutorial: policy` 可执行同源固定手牌与二回合教程策略。返回 trace 中的模型仅标识实体，显示从冻结值读取。它保留既有死亡 / 终局时机：NextPlayerTurn 表示已运行回合初规则，不是额外存活保证。奖励、地图与节点牌堆重置由 Run / GameSession 负责。

## 只推进出牌区

```csharp
using (var session = new BattlePlayZoneResolutionSession(
    player, battle, player.PlayZone, player.MagicBook, readingRanks: null))
{
    session.RunToCompletion(step =>
    {
        // 只观察结果；不要在此重复 Cast、ResolveEnemyDeath 或 ApplyArrowReadAfterAction。
    });
}
```

单独 session 不负责 `BeginPlayerResolveRules` / `EndPlayerResolveRules`，这些由宿主管理。`BeforeArrow`、`BeforeMagicFill`、`BeforeMagicImpact`、`DeathPending`、`BeforeAfterRead` 是规则前停点，下一次 `MoveNext` 才提交对应规则。UI 在这些停点播放原动画，脚本直接连续推进。

- 序列仅 Build 一次，包括真正的读取钩子与规则随机，不是无副作用预览。
- `magics` 与 `readingRanks` 是显式输入。null ranks 使用玩家持久 MagicReadingOrder / MagicModel.ReadingRank，再回退 SlotIndex。UI 采集布局提交同一槽位策略，脚本和保存恢复不读取 Transform。
- 规则保留基础效果先于配方，Token Invoke 先于目标锁定，每匹配注册一次施法；重放、死亡链与首序列读取后动作由核心处理。
- 数值、Buff、意图、牌显示副本固定；结果内模型只代表身份。整批最终模型不能直接用于中间帧，正式 UI 消费 snapshot 和逐击 cue。
- Dispose 不会补完未执行规则，也不会回滚已提交效果；中断续接协议待后续实现。

## 商店事务

```csharp
var shop = new ShopSession(player, economyConfig, magicSlotCapacity: 8, services);
shop.Open(configuredLayers, savedState: null);
player.CurrentShop = shop;

if (shop.TryPurchase(shop.Offers[0], out var receipt, out var failure))
{
    // 到这里扣款、入库、已购和 undo 均已完成；动画不能再次提交。
    int countForFlight = receipt.ResultingMagicCount;
}
ShopNodeSaveData snapshot = shop.ExportState();
```

`ShopGenerationServices` 可注入 RNG、解锁过滤、内容查询和价格修正；默认同步操作进入所属玩家 scope，使用该世界 RNG、内容与成长快照。恢复传入 `ShopNodeSaveData`，直接恢复报价和刷新次数，不消耗生成随机。脚本应通过 session 执行操作，不直接修改可变的 offer / layer 集合。

删箭头先调用 `BeginRemovalSelection`，取消用 `CancelSelection`，选定后调用 `TryRemoveMaterial`；取消不扣款、不消耗按钮次数。普通商品中的删牌报价用 `TryPurchase(offer, ..., removalTarget)`。`TryRefresh`、`TryUndo` 同步提交；撤销保持原绝对金币快照语义，退款不走奖励倍率。同步遗物观察者异常仍可能中断事务，完整故障事务边界待后续统一。

`RuleRunSnapshot` 从 `player.CurrentShop` 导出；`Assets/Scripts/UnityAdapters/RunSaveSystem.cs` 只保留生产 IO / 兼容转发。Hide 不丢弃 session，离开节点才清空。新档含 refreshCount / layerOfferCounts；旧复杂混合层只能按原顺序 / 预算还原，不重抽。

## 奖励棋盘

```csharp
var grid = new BonusGridSession(bonusData, seed: 12345, randomStep: 0);
BonusGridStepResult step = grid.Step(MaterialEnum.Fire);
BonusGridRewardResult reward = BonusGridRewardRules.Apply(
    step, player, modifyGoldGain: amount => amount);
```

只做移动和领取标记时调用 `Step`；发奖统一调用 `BonusGridRewardRules.Apply`，同一步重复提交不重复入账。正常生产不传 modifyGoldGain，沿用当前进阶与遗物加成。同步宿主可连续 Step 或 ResolvePath；正式 UI 逐步提交、移动、播放收益，未提前计算整条路径。

UI 提交阶段通过 `playGoldFeedback:false` 静音，到达后调用纯表现接口播放一次金币声音，规则及遗物事件仍在移动前提交。中断不会撤销已提交收益。Apply 对同一步最多尝试一次，异常后缓存观察到的前后值，不自动重试。

当前存档没有棋盘坐标 / 已领取状态快照，继续沿用原节点检查点，未增加逐格强制保存。不能只持久化金币却在恢复后重建全新棋盘；棋盘恢复必须成套实现。

## 手工视觉验收

在 PC、PE 各用一个普通战斗和一个含死亡链 / 多段攻击的战斗，按下列顺序检查；这些步骤尚未执行：

1. 同起点匹配多个道具，确认当前视觉阅读顺序、材料填充、粒子命中、连击计数、血条和飘字时刻；开启重放后读取后消费 / 返回动作只发生一次。
2. 触发多个敌人死亡与亡语召唤，分别检查死亡重叠配置开启 / 关闭；下一项规则不能越过死亡屏障，视图退场后再布局。
3. 购买道具 / 箭头，确认只扣一次、只入库一次，飞入起点、落点、让位与数量正确；动画结束后撤销一次，重复撤销无效。取消删牌应不扣钱、不占次数。
4. 刷新商店，确认旧商品按原层 stagger 消失、新商品出现、按钮重新可用；恢复同一商店快照后报价、已购、刷新价格与 undo 相同。
5. 奖励棋盘连续移动、撞边、返回旧格子，确认 0.32 秒移动、到达后收益与声音、0.16 秒间隔，旧格子不重领。
6. 单独检查播放中 Hide / Stop / 销毁；目前只保证已提交规则不因纯动画回调漏执行，不承诺完整 busy 释放、取消续接或任意中途存档恢复。

## 命令、整局与检查点

```csharp
// 内容由正式加载器转换后显式传入；Simulation 不写真实 profile / codex / 存档。
GameSessionOptions options = GameSessionFactory.Production(
    seed: 12345, content: catalog, profile: profileSnapshot,
    startConfigId: "balanced", chapterId: 1, contentVersion: version,
    difficulty: new RunDifficultySaveData());
var game = new GameSession(options);
var observation = game.Observe();
IReadOnlyList<GameCommand> legal = game.GetLegalCommands();
GameCommandLogEntry receipt = game.Execute(legal[0]);

// 保存的是初始 archive/profile/seed/构造值 + 实际命令；不是 fingerprint 充当状态。
string json = GameSessionCheckpoint.Capture(game).ToJson();
GameSession restored = GameSessionCheckpoint.FromJson(json).Restore(seed =>
    GameSessionFactory.Production(seed, catalog, profileSnapshot,
        "balanced", 1, version, new RunDifficultySaveData()));
```

- `GameSession.Execute` 支持真实地图 / 节点、Battle / NodeCards、选择回答、ContinueEvent、商店买 / 删 / 刷新 / 撤销 / 离开及 TutorialContinue。合法动作与实际 Execute 均校验阶段，不让脚本绕过教程门控或伪造 Boss 节点。
- `AIBattleHost` 以 `card:n` / `enemy:n` 绑定稳定身份，正常可见 observation 与隐藏诊断分开；规则 query 不 Build 读取、不抽 RNG。UI busy / drag 锁不是核心校验的替代品。
- 选择使用 `PendingChoice.Id` 和 candidate.Id；旧 / 重复 / 超数量 / 不可取消答案返回 ChoiceFailure。回退上一级保留同一候选，不因面板 Show 重抽。
- `RuleRunSnapshot.ExportSnapshot` / RestoreSnapshot / RestoreSnapshotBattle / RestoreSnapshotCommands 用于稳定决策点的内存分支，保留 runtime graph。旧持久 DTO 不含全部 packed/runtime，不宣称与该快照等价。
- 正式事件 / 战后奖励只保存完整事务；PendingChoice 与自动基础金币阶段受 guard 保护。中途退出回最近完整节点，脚本 checkpoint 可重放到相同选择。

## 独立 .NET 入口

`Standalone/MaterialMagic.Core.csproj` 链接真实生产源；`Standalone/MaterialMagic.Smoke/MaterialMagic.Smoke.csproj` 加载真实 JSON，执行地图 / 回合 / 双局 / replay / checkpoint / 事件 / 商店 / Run smoke。

```sh
dotnet build Standalone/MaterialMagic.Smoke/MaterialMagic.Smoke.csproj --nologo
dotnet --roll-forward Major Standalone/MaterialMagic.Smoke/bin/Debug/net8.0/MaterialMagic.Smoke.dll "D:/Unity/Unity Project/MaterialMagic"
```

第二个参数可传 Unity 导出的 `RuleContentArchive` JSON，以包含真实 SO 覆盖。只读 JSON 模式不冒称覆盖了所有 SO。无需外部 AI 模型即可用合法动作脚本；没有安装新 runtime / 包或调用 DeepSeek。最终编译 / 测试记录以实施计划为准。
