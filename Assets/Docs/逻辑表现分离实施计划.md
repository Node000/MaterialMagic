## 核心规则与演出契约

- BattleTurnDriver 同步完成箭头、道具、重复施法、死亡屏障、回合末、敌人整行动组、多段逐击与下一回合初。UI 不在动画回调中再次执行这些规则。
- 读取序列只 Build 一次；基础效果在对应 token 前；Invoke 后才锁定施法目标；每个匹配 RegisterMagicCast 一次；首序列读取后动作一次；早胜利仍执行 after-read；敌人整行动组之后才排死亡。
- trace 内模型引用是稳定身份，不是显示值。显示使用冻结快照和 detached 卡牌副本；逐击反馈只在对应 checkpoint 播放一次。新增召唤 / 旋涡抽牌视图在首次对应快照创建，不提前回收待退场视图。
- 同步 owner scope 不能跨 yield / await。同 owner 嵌套保留 Token / EnemyBuffChanged，异 owner 调用和异常退出恢复先前 ambient；反馈 capture 与规则 RNG 分开。
- 提交 EndTurn 后不允许演出中换焦点或重排规则输入。这比旧的“施法间点击换焦点”收紧，是整回合原子提交所必需的交互边界。
- 商店 / 奖励收据中的数量与前后值是权威值；飞入不能再用 Count + 1 或重复入账。奖励格子仍按单步规则提交，不改变原移动时长 / 间隔参数。

## 保存与恢复边界

1. `RuleRunSnapshot` 负责纯 DTO 与内存分支；`RunSaveSystem` 负责真实 slot / 路径 / 时钟 / IO 并转发纯算法。Simulation 不写真实图鉴、成长、统计、声音或存档。
2. 内存 FullGraph 保留跨牌堆共享身份、linked / packed、附魔 runtime、临时 ID、收费牌和回合状态；敌人补派生 runtime 与 Buff / 意图。只在死亡 / 遗物队列已稳定的决策边界捕获。
3. `GameSessionCheckpoint` 是带初始内容 archive / profile / difficulty / seed / 初始化值与命令日志的可恢复重放检查点。恢复需同语义 options factory；PendingChoice 通过同一规则重放到达，不把 fingerprint 当作完整状态。
4. 正式旧 JSON 材料 DTO 继续兼容；不声称它已经拥有 memory FullGraph 的全部 packed / runtime 表达能力。没有引入任意演出中途的磁盘恢复格式。
5. 正式奖励 / 事件未持久化完整 PendingChoice DTO，中途不保存半笔收益；整个奖励事务及选择期 guard 返回最近完整 checkpoint。内存会话可保持同一候选，整局脚本 checkpoint 可恢复候选。
6. 正式奖励棋盘仍沿用节点检查点，不只保存金币后重建新棋盘。商店完整事务保留 ForceSave，并恢复刷新次数 / 商品层数量。

## 程序集与独立运行

- `Standalone/MaterialMagic.Core.csproj` 链接实际生产规则源，不复制效果；不引用 Unity DLL、UGUI、TMP、DOTween。数学值 / Resources / JSON / profile 的外层适配器只补宿主边界。
- `Standalone/MaterialMagic.Smoke/` 使用真实 Resources JSON，可额外输入 Unity 导出的 RuleContentArchive，保留敌人 SO 覆盖优先级；不使用 YAML 重建 SO 内容。
- Unity Core 边界的验收是无 UGUI / TMP / DOTween / Presentation 反向依赖。Unity 内仍可保留数学与作者配置 SO 类型，不能夸称 Unity Core 无 UnityEngine 类型；真正无 Unity DLL 的执行边界由独立 .NET 构建验证。
- Reflection 附魔工厂与全部具体附魔保持同一 Core 程序集；迁移添加 MovedFrom，保留 `.meta`，不批量保存美术资产。
