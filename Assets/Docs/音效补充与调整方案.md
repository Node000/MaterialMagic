## 3. 连击音效核查结论（你问的第 2 项）

**结论：算"半实现"——有变调，没有专属连击音色。**

现有机制：

- `HandSystemUI.PlayPlayerCastSwingSfx(int continuousCastCount)`：播放 `GameSfxId.HitPitch`，pitch = `playerCastSwingPitchBase(1.0)` + (连击数-1) × `playerCastSwingPitchIncrease(0.08)`，上限 `playerCastSwingPitchMax(1.45)`。
- 连击数来源：`pendingCastShakeCount = battleManager.ContinuousCastCount + 1`，在 `HandleCastReleaseFrame`（施法释放那一帧）调用一次。
- `ComboView`（COMBO N 文本 + punch/抖动/倾斜）只做视觉，**没有任何音频调用**。

缺口（需要你确认方向）：

1. 一次施法释放只播 **1 次**，不是每个箭头一次。
2. pitch 在第 6 连击就封顶（1.0 + 5×0.08 = 1.4，第 7 次会算到 1.48 被截到 1.45），高连击没有继续升级的手感。
3. 只有"音高"一个维度在变，没有音色/层次变化，也没有连击中断或结算的收尾音。

可选方向（见 §7 决策点 1）：保留变调只换素材 / 改成按连击等级切换素材（备选包里 `Rise01..07` 正好 7 个）/ 变调 + 叠加达成提示音。

### 5.4 导入时必须注意的两点（实测发现）

1. **响度差异极大**：工程现有 SFX 已经做过增益（例如 `damaged.wav` 峰值 52.6% / RMS 27%，`hit_pitch.wav` 峰值 100% / RMS 32%），而下载包里不少文件很轻（`Cardsounds/tap.wav` 峰值 5.1% / RMS 0.9%，`playcard.wav` 峰值 16.8% / RMS 0.9%）。直接混用会出现"某些音效几乎听不见"，导入后需要统一响度（例如整体对齐到 -16 LUFS 左右或按峰值归一）。
2. **格式与声道**：`.ogg`（Kenney）、`.aif`（SoundPack01）、`.wav`（其余）Unity 都能直接导入，但 `.aif` 多为双声道、`.ogg` 多为单声道；建议导入后统一 `Load Type = Decompress On Load` + 单声道 + 短音不做循环，避免出现 "只有一边耳机响" 的问题。

## 6. 新增 GameSfxId 的序列化注意（实施前提）

现有枚举是**显式数值**（`None=0 … NotEnoughMoney=7`），并且 `gameSfxClips` 已按 `id` 序列化进 `Assets/Scenes/StartScene.unity/AudioManager/AudioManager`。

因此：

1. 新增音效**必须追加新数值**（8、9、10…），不能在中间插入或重排，否则已保存的场景绑定会串位（例如"消耗金币"绑到"受伤"上）。
2. 新增时要同步三处：`GameSfxId` 枚举、`AudioManager.gameSfxClips` 字段初始值、`AudioManager.EnsureSfxClipEntries()` 的补条目列表（该方法负责给缺失项补空条目，让 Inspector 能显示出来）。
3. 顺手可做的事：把已有但未接入的 `Buff` / `Debuff` 纳入枚举（素材现成）。
