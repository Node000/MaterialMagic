## 96 · 同类箭头附魔可叠加，层数显示在信息框右上角

- **已实施**：`stackable` 仅为充能、流动、引燃、坚固、漩涡、复读、增殖对应的七个定义启用（配置 ID：`charge`、`flow`、`kindling`、`sturdy`、`vortex`、`repeat_arrow`、`proliferating_arrow`）。临时和结构性词条仍不可叠。详情预制体已绑定独立 TMP 角标和专用白描边材质；规则回归验证了实例独立、复读累加、顺序与存读，视觉仍待运行确认。
- **规则**：在 [`GameDataTypes.cs`](../Scripts/Data/GameDataTypes.cs) 的 `MaterialModel.AddModifier()` 统一叠加和校验。按附魔定义配置是否可叠加，不把临时／结构性标记和层数可累加的效果混为一谈；同类每层保持独立实例。手动、批量、奖励目标共用资格判定，只有实际加上才完成选择；核对 [`EventResolutionSession.cs`](../Scripts/Simulation/EventResolutionSession.cs) `ApplyDeckModifier()`、`OpenMaterialModifier()`、[`HandSystemUI.cs`](../Scripts/HandSystemUI.cs) `TryApplyPendingMaterialModifier()`，以及 [`RuleMaterialCodec.cs`](../Scripts/Simulation/RuleMaterialCodec.cs) 的存读和显示拷贝。
- **表现**：[`UnifiedDetailContentBuilder.cs`](../Scripts/UnifiedDetailContentBuilder.cs) `BuildMaterialAddedDetails()` 按附魔 ID 合并信息框，独立传层数（不拼到标题）；由 [`UnifiedDetailPopupUI.cs`](../Scripts/UnifiedDetailPopupUI.cs) 转交 [`AddedDetailedUI.cs`](../Scripts/AddedDetailedUI.cs) `Apply()`。在 [`AddedDetailed.prefab`](../Prefabs/UI/AddedDetailed.prefab) 的**框体右上角**设置独立数字角标，2 层起显示，普通单层和其他详情不显示；标题右侧预留角标宽度，长标题和滚动正文都不遮住它。字体复用局内 `AscensionIconButton/LevelText`、`ChapterProgress` 实际使用的 `Assets/Resources/Fonts/PingFangYuTongTi-2 SDF.asset`，不是开始菜单当前的普通字体。给数字专用 TMP 材质或局部变形组件：蜡笔质感、较大的字形波动扭曲、白色描边跟随字形一起变形；参数由 Inspector/材质调，不改公用字体材质，不让整框抖动，也不拦射线。
- **验收**：同一牌叠两次实际生效，详情右上角显示层数；存读后数量和顺序一致；不可叠附魔被拒绝且不会消耗奖励；切到单层详情不残留角标。

## 98 · PE 道具栏固定空格与触摸拖放

- **已实施**：`SampleScene_PE` 沿用 [`MagicBookRowLayout.cs`](../Scripts/MagicBookRowLayout.cs) 的现有格尺寸和列排布；按容量常显槽壳，从独立非射线拖影投放到实际槽位。投放空槽只搬移该道具，投放占用槽按视觉阅读顺序插入并保留中间空位。PE 发放查真实空槽，卖出和重排后强制保存，PC 仍走原弧形和压实路径。实际触摸及续玩显示待验收。

- **主入口**：[`HandSystemUI.cs`](../Scripts/HandSystemUI.cs) `CreateMagicViews()`、`GetMagicBookDropPreviewIndex()`、`EndMagicBookDrag()`；[`PlayerState.cs`](../Scripts/Data/PlayerState.cs) `RearrangeMagicSlotsByVisualOrderCore()`、`NormalizeMagicSlotsCore()`；`MagicBookRowLayout.Arrange()`。
- **验收**：真机拖到同列、跨列和末尾空格，栏外释放不提交；拖影不干扰落点；留空、卖出、续玩及战斗触发顺序一致，PC 排序不回归。

## 104 · 开始界面进阶入口改明显，抽屉不挡确认

**已观察到的原因**：[`StartScene.unity`](../Scenes/StartScene.unity) 的 `StartMenuCanvas/MenuContentRoot/StartConfigPanel` 下，`AscensionDrawerPanel` 与 `StartConfigActionButtonGroup` 是兄弟，抽屉位于按钮组之后。当前抽屉宽 1080、高 260，序列化展开位置为 `(0, -725)`；在已保存的展开位置上，抽屉矩形覆盖 `ConfirmButton`，抽屉背景 `Image` 可接收射线。`SetDrawerOpen(true)` 会再开启 `CanvasGroup.blocksRaycasts`，与遮挡现象相符。本轮只做只读检查，未用实机点按复现。

**拟改布局（先审美术，不直接改坐标）**：

1. `AscensionToggleButton` 挪到开局配置操作区的固定位置，与确认、返回并列，不再像孤立的右侧小数字。文案用「进阶」＋ `A0 / A+N / A-N`，加展开方向提示和明确触摸面积。锁定时仍可展开看解锁条件，只禁用 `−/+`。绑定现有进阶等级／锁定逻辑，不另存一套。
2. 为角色配置和进阶详情预留独立内容区域；确认、返回留在永远可见的操作区。宽屏详情可用配置区侧栏，窄屏在同一内容区域展开可滚动详情、压缩正文可视区而不覆盖操作区；正文滚动仍能拖，配置切换、详情展开都不应把确认盖住。优先在 `StartScene` 搭容器、锚点与 Inspector 引用，保留现有窗口美术和按钮文案。若细节布局最终采用单一版本，也要在最窄支持分辨率满足这些约束。
3. [`StartAscensionSelectionUI.cs`](../Scripts/StartAscensionSelectionUI.cs) `Refresh()` 只驱动等级、提示和锁定显隐；`SetDrawerOpen()` / `SetDrawerImmediate()` 管动画与可点状态。背景／边框／文字等纯装饰不拦射线，滚动命中区和实际控件保留射线；关闭动画一开始即停止拦截。打开或关闭不重置选择；继续存档不误用菜单预选等级。
4. **验收**：PC 鼠标与 PE 触摸，宽屏与最窄目标比例，A0／负进阶／正进阶与未解锁，打开／关闭／快速切换、正文长到需滚动、中英文。用 `EventSystem.RaycastAll` 检查确认按钮在展开、收起及动画途中不被抽屉挡住，再真实点击验证开始／返回；不能以 `onClick.Invoke()` 代替。

## 106 · “你更习惯哪种模式？”现行三个选项

事件 ID `event_input_setup`，标题“新手按键设置”。事件手牌配置抽 2 张；手柄和键鼠两个选项各随机一个不重复的箭头配方。实际效果见 [`EventData.json`](../Resources/Data/EventData.json)、[`EventModel.cs`](../Scripts/Data/EventModel.cs) `TryGetMatchedOption()` / `TryGetExitOption()`、[`EventResolutionSession.cs`](../Scripts/Simulation/EventResolutionSession.cs) 的事件效果分支。

| 选项 | 实际效果 |
| --- | --- |
| 手柄模式 | 清空当前金币，按顺序尝试获得【保护色】、【叶绿体】；剩余槽位不足则少拿或不拿，不换旧道具。 |
| 键鼠模式 | 清空当前金币，按顺序尝试获得【雨幡】、【贴纸】；同样受槽位限制。 |
| 先不设置 | 没匹配前两项时走退出选项；**获得基础 5 金币**，不获取道具。 |

三项都不会实际修改输入设置。第三项从 `LoseGold(2)` 改为 `GainGold(5)`，经过常规金币增益修正；已同步中英文说明。前两项满栏仍清空金币；发放只占实际空槽，空槽不足少发，不覆盖已有道具。

## 108 · 雨幡效果是否正确

- **配置**：`MagicData.json` `magic_rain_banner`（37）配方是 **上 → 下 → 右**。只装备雨幡且配方被读到即可施放。`EffectType=DrawNextTurn` 是其他逻辑读取的分类，不表示实际触发时机，本次保持不变。
- **当前规则**：确认打出后先弃旧手牌（尊重保留），出牌区继续读取；雨幡达到配方即发动，生成 5 张临时下箭头到当前手牌。结算后只清空出牌区，新牌自然留到下一回合，不再使用雨幡专属的延迟队列。
- **主入口**：`BattlePlayZoneResolutionSession`、`BattleTurnDriver.ResolveTurn()`、`RainBannerMagicModel.ResolveCast()`。回归测试覆盖弃手先于读牌、配方完整才施放、发牌先于出牌区清理、新牌下一回合可用以及下次正常确认弃手时移除。

卵的 `OnDie()` 已走标准受伤入口，改共用回合收口而非卵脚本特判。在 [`BattlePlayZoneResolutionSession.cs`](../Scripts/Simulation/BattlePlayZoneResolutionSession.cs) `Resolve()` 和 [`BattleTurnDriver.cs`](../Scripts/Simulation/BattleTurnDriver.cs) `ResolveTurn()` 的亡语连锁排空后先查玩家 HP，再决定能否继续读箭头、敌方行动、开下回合或判胜。零血失败只报一次；敌我同归于尽不弹奖励。补实际蝇王＋卵用例，覆盖蝇王仍在、玩家与最后敌人同死、非致命爆炸三条路径。

## 补充 · 箭头附魔和道具附魔的掉落权重

**建议两类都配，并共用一套按权重不放回抽样。** 现有道具附魔 [`MagicModifierData.json`](../Resources/Data/MagicModifierData.json) 已有 `weight`，但正式 UI 和默认事件服务只用它排除 0，正权重之间实际等概率。箭头附魔的配置源是 `Assets/Resources/EnchantConfig/MaterialModifiers/` 的 `MaterialModifierDefinition`，目前只有是否入池和价格差，没有权重。新增权重不是让每个附魔都进掉落池。

1. 道具沿用原 `weight`；箭头在 [`MaterialModifierDefinition.cs`](../Scripts/Data/MaterialModifierDefinition.cs) 加 `weight`（默认 1），并通过 `CreateRuntimeData()` / `SetData()` 传给 [`MaterialModifierDisplayDatabase.cs`](../Scripts/Data/MaterialModifierDisplayDatabase.cs) 的 `MaterialModifierData`。首批都默认 1 保持平衡，后续按设计调整；0 不参与随机掉落，负数报配置错误。
2. 放在规则层统一抽取：先筛入池标记、解锁和可应用目标，再按稳定 ID 排序，用该局随机流和正权重无放回抽取，候选少时返回实际数量。接入 [`EventRuleServices.cs`](../Scripts/Simulation/EventRuleServices.cs) 和 [`HandSystemUI.cs`](../Scripts/HandSystemUI.cs) `GetMagicModifierChoices()` / `GetArrowModifierChoices()`；同一规则覆盖精英奖励、随机事件／休息选择和脚本宿主，避免当前 40 次抽重复的上限。普通道具品质权重、附魔价格不动。
3. 固定事件按 ID 发放仍可按原规则发；商店弱／强附魔分池与价格已有单独配置，这一轮默认不改商店投放。若后续要加商店权重，先按附魔抽再选箭头方向，避免同一附魔因为商品表列了多种方向而暗中放大投放率。
4. 验收同 seed 候选一致、候选不重复、零权重不进随机池、无可用目标不出候选、不同权重多种子统计符合相对频率，固定发放不受影响。
