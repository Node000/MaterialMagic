# 二层 3D 与小地图生成规划

> `Assets/Scenes/2层制作测试.unity` 用于固定图、Pattern 和已发布地图池联调。旧场景、Prefab、主题和正式章节入口保持不变；正式内容绑定待定。

## 一、四套现有内容怎么用

| 现有入口 | 直接复用或作为参考 | 不沿用的部分 |
| --- | --- | --- |

## 二、统一输入，分开运行状态与表现

```text
PlotWeave（模板/生成）或以后另一个全图生成来源
  → floor JSON（地板 + 开放边 + 门边）
  → SecondFloorFloorMap（只读布局；导入时转换一次坐标）
  → 一个探索会话（格位 / 朝向 / 当前可见 / 已发现）
        ↘ 3D：建表面和边界；读取状态做表现
        ↘ 小地图：同样的格、边和玩家状态；不再单独推进
```

- `Assets/Resources/Data/Maps/Patterns/project.json` 是工作目录保存的设计文件，不当作运行地图。`Preview.floor.json` 和以后具名地图的 `cells/edges` 是物理权威。`open` 是空通路，`door` 在读入时是可通行的潜在连接；正式门禁/门扇状态另外存，不在游戏里改地图文件。可见性和通行以后按独立规则判定，墙始终挡两者。
- `FirstPersonGridExplorationSession` 可复用转向、移动提交、朝向直线可视的框架；新增边查询输入而不是把旧 Boss 揭示硬接到所有地图。3D 相机与小地图读取同一个探索状态。保留旧原型的调用方式作对照。
- 放置集合不再等于一条直线有序序列。旧《系统实现方案》《代码架构》里 `OrderedCells` 连续共线的假设不用于生成几何。内容有严格顺序时另用已确认的路线/槽位，不从 `{x,y}` 排序、数组顺序、或临时选的一条 BFS 路径推断。

## 三、建议开工顺序

### 1. 固定图联调：先一份数据生成两种表现

打开 `Assets/Scenes/2层制作测试.unity` 并进入 Play Mode。`W` / `↑` 前进，`A` / `←` 左转，`D` / `→` 右转；也可点击画面中间或左右三分区。右上小地图只显示以角色为中心、每轴 7 格的局部窗口，最外圈沿格中心裁切（四角只露四分之一格）；地图边缘没有地板的地方保持空白。默认保留探索雾；Inspector 中的 `Show All` 只关闭这块窗口内的探索雾，不扩大窗口。地板均显示为独立方格；仅在相邻格边上用深色标内墙、青色标门，不连格心。小地图随方向旋转，正前方总在上面，主角使用与一层相同的 `Assets/Resources/Images/UI/PlayerSmall.png`，固定在中心并保持正立。

- **3D**：按唯一地板格放地面和顶板；按唯一的无向格边放墙或门。任意地板到空域是外墙；两个地板但无开放边是内墙；门用独立门框，不叠墙也不加门禁碰撞。首版只复用 Whitebox 的结构网格、材质和高度配置，不生成 Scribble、装饰或 cutaway，也不做区域主题映射。
- **小地图**：UI 容器和主角 Image 在场景中配置，不为每一格临时搭 UI。已发现和当前可见由探索会话统一提供，窗口从原图按格裁切，不修改地图数据。
- **手动对照**：Inspector 选择 `Snapshot` 后，可读原来的 `Preview.floor.json`。右转朝南会正对内墙，不能直穿或揭示墙后的格子。添加对应 `S/open` 边并在 Unity 重新导入后，内墙与小地图墙边标都消失，同时允许向该方向移动和揭雾。

### 2. Pattern 样例与生成图联调

`Assets/Resources/Data/Maps/Patterns/Sample.patterns.json` 是 PlotWeave 网页导出的 v3 模板库，包含通用模板和仅限 `city` 的 2×2 折返样例。制作场景默认使用 `Published Pool`，绑定 `Assets/Resources/Data/Maps/SecondFloor.map-pools.json` 的 `level-1 / standard-triangle`，初始种子为 `7`。「重载地图」重跑当前种子，「下一种子」生成另一布局。`Generate From Patterns` 仍可用场景参数单独试模板。图上 R/D 是条带资源/难度合计，不是发放奖励。

PlotWeave 第二页在 Unity Edit Mode 下调用同一 C# 生成器预览，然后把配方发布到资源目录；游戏可用 `SecondFloorMapPools.Generate(poolId, seed)` 按权重选配方。A/B/C 是顺序槽，模板按区域类型匹配；样例为城市 / 城市 / 郊区。当前生成包括各区成环、三座独立桥、`noLoop` 末端、模板使用上限与跳数等级。资源/难度是软目标，在有限搜索中优先较接近的有效布局。当前网页预览和运行时在同配方、同模板库、同种子及同生成器版本下相同；旧单层工具仍是独立算法。不含共享格交叉或区域主题映射。

墙段优化放在白盒正确之后：能合并的段必须同主题、同方向、连续且不跨门/动态边，保留局部更新索引。之前的原型调研已经看到高顶点引用量和手绘面可能重复初始化；那不是当前帧率证据。先记录几何实例数、Scribble 初始化次数、稳定帧与渲染开销，再决定分段或缓存。先不改现有手绘参数和 Prefab；视觉改动交审阅。移动与转向绝不能导致几何重建。

### 3. 正式内容另批接入

等两种表现同图稳定后，再决定上部 U / 传送、Boss 位置、领域门禁、奖励终端及战斗房间的触发范围；不以 2×2 的几何形状直接推断遭遇数量。正式战斗沿用 `RunSession` 的结果/奖励收尾，在运行档另存地图身份、玩家格位、朝向和持久状态；新读图不会覆盖旧档。此阶段不阻塞开始做 3D 和小地图。
