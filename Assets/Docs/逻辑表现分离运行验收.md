## 实际改动与编译

修复 `Assets/Scripts/HandSystemUI.cs:3426` 的调试战斗输入门控：`DebugStartBattleLevel` 已把 BattleManager 切到 PlayerTurn，却未把 RunManager 从地图态切入 Battle，导致真实点击命中手牌但不出牌，出手 / 刷新也禁用。现沿 GetCommandSession 已有的 debugBattleActive 语义允许调试战斗输入，同时保留 busy、选牌事务与 PlayerTurn 检查。没有改正式随机、存档格式或 Scene / Prefab 美术值。

该文件热更新受当前 Mono 非公开类型访问限制未应用，之后完整编译 / domain reload 成功。复测基于完成编译后的代码。

## 运行方法和证据范围

- 初始为 clean 的 `Assets/Scenes/StartScene.unity`，在临时空场景进入 Play，运行态加载目标场景。没有保存主体场景或改动场景资产。
- 在目标 Awake 前注入 Simulation PlayerStateServices、内存 profile / policy，关闭 runtime analytics；不走菜单、新局删档、正式商店 LoadCurrentRun 或结果页清档。
- 首次 PC 入场后才发现 EmitAscensionSelect 直接读 UnlockProgressSaveSystem 的旁路，因此这次入场不能描述成严格零用户档读取；工具没有输出或复制该档内容，也没有故意进行真实档写入。后续重进 PC / PE 用临时 active scene 名 `SampleScene_PC_SecondFloor` 跳过该分支，并保持教程保存保护，Awake 后切回目标场景、directSampleDebugRun=true、secondFloorRun=false，关闭教程门控。
- 这些是隔离 debug 场景，章节/进阶初始化与正常菜单开局不同，不证明正式菜单、真实槽位和地图完整流程。Simulation 服务也不证明所有音效、图鉴、成长与后台反馈。
- 点击均先 `EventSystem.RaycastAll`，验证首命中解析出的 IPointerClickHandler 属于目标，再执行 pointerDown / pointerUp / eligibleForClick 时 pointerClick。不是 Button.onClick.Invoke。
- PE 在 Windows Editor 的 1920×1080 Game View，用 pointerId=0 的事件检查目标路径；不是手机真机触控、长按/滑动或不同宽高比验收。

## 发现的问题和未覆盖项

1. **reload 诊断未解决。** 本轮完整编译后再次出现 `Objects are trying to be loaded during a domain backup`（一次观察合并 count=24）。随后 Play 还可见 linkedCards 递归序列化 depth10 警告，根包括 HandCardView.card / MaterialCardView.materialModel。已有 linkedCards 类型结构会触发 Unity 备份限制；不能仅凭它断言普通运行栈溢出，也不能声称 Console 全干净。
2. **RewardOption2 缺脚本警告。** 运行日志出现两次 `The referenced script ... (Game Object 'RewardOption2') is missing!`，另有两次 Unknown 缺脚本警告。后来 PE 活跃场景全树检查 missing scripts=0，说明仍须追踪未激活模板 / 实例化或短生命周期对象来源；没有擅自删除组件或重建资产 GUID。
3. **正式磁盘恢复仍未验。** 未对用户正常档做保存→退出→继续，也未做进程强退 / 文件写入中断。当前保存守卫、既有规则测试和只读源码审查不能代替这类端到端实验。
4. **未覆盖**自然战斗胜利→奖励→自动商店、额外 Boss 整局、演出中退出恢复、真机 SDK、真机触摸长按与多分辨率、英文长文/缺字全面检查。
5. **随机数仍有防 SL 缺口。** 详见独立审查；当前仅修改了调试输入的一行条件，没有实施随机数修复。
