# 遗物系统逻辑实现说明

## 范围

本轮实现纯规则层：数据、工厂、实例状态、玩家库存、提交事实、派生效果、Buff/战斗联动、候选领取和快照保存。没有 UI、MonoBehaviour 遗物控件、新场景或对现有场景/Prefab 的修改。按用户补充要求，不制作表现层；后续如制作测试 UI，仅在独立 `Relic-Test` 场景进行。

不实现二层门控，不自动接入精英奖励/现有商店商品/EventRewardType.GainRelic，不向普通流程自动发放测试遗物。原设计中的完整投放和 UI 是后续接入，而不是本次已完成能力。

## 使用入口

```csharp
// PlayerState / PlayerStatus 都拥有独立库存；无静态遗物单例。
var player = new PlayerStatus(50, 20);
player.TryAcquireRelic(2); // ArrowPulse，具体 ID 来自 RelicData.json。
var battle = BattleManager.Create(player);
battle.AddEnemy(enemy);
battle.BeginBattleRules();
battle.BeginPlayerTurnStartRules(0, null);

// 直接测试读取规则，无需 HandSystemUI、Canvas 或场景。
var step = new ArrowReadStep(new MaterialModel("test", MaterialEnum.Fire), 0);
step.AddBaseEffectDirection(MaterialEnum.Fire);
MagicCastResult result = ArrowStepRuleResolver.Resolve(player, battle, step);

// 创建并固定候选。Create 自动写入 player.PendingRelicOffer；未领取时再次请求同池不会重掷。
var offer = RelicOfferService.Create(player, "relic_test", 3, paid: false);
RelicAcquireResult acquired = RelicOfferService.TryClaim(player, offer, 0);
// 正式渠道编排器需在成功后调用自己的安全快照入口；服务本身不依赖 UI/文件 IO。
```

`RelicOfferService.TryClaim` 只接受当前 PendingRelicOffer 对应 offerId，以玩家持有的候选和价格为准，拒绝重复领取/过时副本/无钱。选择与扣费同一同步逻辑操作；存档仍由调用者在操作完成后统一提交。Create 无放回按权重选择，排除已持有，候选不足返回较少数量，不无限重抽。

## 已接入的事实和生命周期

- 获得遗物（只给新增实例，不在读档时重播）。
- 战斗开始、玩家回合准备/开始/结束前后、战斗胜负结束。
- 真实普通抽牌、入手、箭头步骤读取（带 replay）、实体箭头消耗、每次施法开始/完成（包括重放）。
- 普通伤害/生命损失、玩家护盾、治疗、金币、Buff 施加和可观测层数变化。
- RunManager.ClearCurrentLevel 在确有 CurrentLevel 时发布 NodeCompleted，清空后再次调用不重复；Amount 是结束关卡 numericId。该钩子仍跟随现有节点完成边界，未重构自动商店与 Boss 流程。

布置/撤回/排序不算使用箭头；BuildSequence 不发布读取事实。换牌补充沿用旧规则，不算普通抽牌。单个步骤重读可观察，但示例 ArrowPulse 不计重读。基础效果多次执行仍算一个读取步骤。

## 交互与顺序

### Buff

施加保留原来的来源 OnGiveBuff → 目标 OnReceiveBuff → 合并/覆盖 → 来源 AfterGiveBuff 链，在适当阶段追加遗物的纯修正。遗物通过 RelicContext.GiveBuff 施加时来源为玩家，所以负面增幅、泡沫板、ExtraDraw→法强等反馈可以自然触发。

BuffApplied 携带实际提交瞬间的 Before/After，避免旧 AfterGiveBuff 又改变状态造成回报失真。通用 Buff 钩子与消耗入口记录净变化，追踪已登记的嵌套增减，避免父子重复通知。兼容旧 Buff 直接写 stack 的净变化；不承诺同一钩子内部所有无通知裸写的中间步骤。批量 ClearBuffs/恢复不广播施加或战斗收益，防止清场触发无限奖励；未来需要精确清理原因时再扩展，不假装已有完整变化原因协议。

### 伤害

- `EffectDamage`：遗物默认普通伤害，不走进攻方 OnAttack/AfterAttack，走目标易损/护盾/受击反馈。
- `Attack`：显式攻击，走玩家攻击 Buff、攻击数值遗物修正和后置攻击链。
- `HealthLoss`：明确失去生命，跳过护盾和普通受击反馈。

事实的 Amount 是真实 HealthDamage，不读取可被 AfterAttack 修改的表现返回值；另含 RawDamage、FinalDamage、ShieldDamage、TargetDied。提交时先登记外层伤害事实，再执行旧同步反射，等规则安全返回再分发，所以外层与嵌套顺序可解释。死亡仍通过既有队列，不直接销毁敌人。

### 队列与防环

BeginOperation 的短同步作用域结束后，先按提交顺序分发事实，再执行 FIFO 遗物效果；效果产生的新事实优先完成分发，再处理后续效果。每次事实冻结当时库存，按获得顺序执行，新遗物不补收过去事件。

派生路径包含“遗物实例 + 钩子类型”，阻断同一路径重入以及 A→B→A。独立命中是独立路径，不吞正常多段。同一根操作超过 1024 工作项或回调异常，库存标为 faulted，禁止导出半结果，应加载最近检查点。不会把问题静默吞掉继续保存。

数值修正函数不允许写状态/抽随机/产生效果，因而可用于预览；一次性次数在正式事件里提交。新事件有会话内递增 EventId，OriginRelicId 标识直接发出遗物实例。尚未实现原大方案的全套 RootAction/CastId/逐层来源追踪，不保证聚合燃烧每一层能归属最初施加者。

## 保存

RunSaveSystem 版本为 4，PlayerSaveData 新增 relics 和 pendingRelicOffer。v3 缺字段恢复空库存；未知 ID/script/stateVersion 保留原状态为 UnavailableRelicModel，不自动丢弃或补偿。恢复不重播 Acquired，不修改金币，不推进局内随机。

PlayerCombatSaveData 新增 runtimeBuffs，BuffModel 提供显式 ExportRuntimeState/RestoreRuntimeState；为当前拥有私有规则字段的 Buff 子类保存待下回合标记、诅咒待处理牌数、伤害计数等，防止遗物恢复了而联动 Buff 丢状态。通过工厂白名单恢复，不保存 CLR 类型名，不经 AddBuff 触发。

仅在遗物操作 settled 且未 faulted 时允许导出/SaveCurrentRun。仍沿用既有节点检查点频率，**不承诺任意动画中途或每次操作即时落盘**；旧战斗协议中其他临时额度/随机附魔状态的全面保存、奖励 UI 阶段和场景路由都没有在本轮完整重构。正式投放编排器接入时，需要领取状态和节点阶段一起保存。

金币动画原先每个飞行金币到达时调用 AddGold(1)，现在改为一次规则提交，动画只推进显示数字，避免遗物按动画粒子数量重复加成。现有商店撤销退款明确标记 Refund，避免退款被当成收益。

## 测试与环境

测试脚本：`Assets/Tests/Editor/RelicSystemTests.cs`。已通过的正式 EditMode 回归包括遗物及 PlayerRoundBuffLifetime、EnemyDeathQueue、ArrowReadSystem、AttributeDisabledBuff、ForceDiscardAll、MagicMatchOrder；最终运行74项，全部通过（含35项RelicSystemTests），失败/跳过均为0。

按用户明确批准，测试依赖从 com.unity.test-framework 1.1.33 升至 1.4.6（NUnit 自动依赖 2.0.3）。升级中发生旧程序集热重载错误，Editor 重启后正式测试通过。没有修改 PackageCache 源码；出现过 immutable package 变化提示，发生在升级刷新后，本轮不以删除缓存方式处理。

只参考公开 Mod API/开源框架，不读取或复制商业游戏源码，不引入外部依赖：

   - 严格检查触发 context；实例 extra 状态；效果通过统一入口处理；延迟执行要捕获上下文，不能引用后续被替换的 context。

   - 独立遗物子类与实例构造。不照搬 Java 反射 makeCopy，项目使用显式 C# 工厂。

   - 遗物扩展基类、数据/本地化/图像边界；本轮仅借鉴规则结构，不复制其贴图/UI实现。
